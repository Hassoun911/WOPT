## Date-stamp convention from 2026-08-23 forward

Use ISO date format `YYYY-MM-DD` everywhere practical.

- Release branches: `release/<product>-YYYY-MM-DD`
- Work branches: `work/<product>-YYYY-MM-DD-<purpose>`
- Build artifacts: `Hassoun-<platform>-<version>-YYYY-MM-DD.<ext>`
- Release notes: `docs/releases/YYYY-MM-DD-<product>.md`
- Website milestones: include the date in deployment marker/release note.
- Watch packages: include the date in APK/package/release label.

`*-current` branches may exist only as convenience aliases. The dated branch is the immutable recovery/reference point.

## Safety rules

1. Never delete or rewrite a dated release branch after it is declared working.
2. Never build a new Android feature directly from an old experimental branch when a dated working release exists.
3. Website work stays in `pwa/`; Android app work stays in `mobile/`.
4. Wear OS work uses the watch release/work branches and should not be mixed with phone APK changes.
5. Before major work, create a new dated branch from the latest verified product reference.
6. A build is not called working until its workflow is green and the installable artifact is verified.
