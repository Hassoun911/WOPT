# Hassoun — Current Project Map

This is the **first file to open for any Hassoun work**. The authoritative branch is `main`.

## Core build architecture

### One shared Android APK
The current Android APK is shared by all three of these modes:
- Android phone
- Tablet / large-screen display
- TV / Masjid TV / wall display

These are **not separate APKs right now**. A change intended for phone, tablet, or TV must be checked against all three before the shared Android APK is released.

Canonical Android APK build:
- Workflow: `.github/workflows/tablet-build.yml`
- Generated APK path: `mobile/android/app/build/outputs/apk/release/`
- Shared source root: `mobile/`

### Separate builds
- Wear OS watch: separate native project under `wearos/`
- iOS: separate Apple build from the shared Expo source under `mobile/`
- Web/PWA: separate web build under `pwa/`, deployed for `hassou.app`

## Important architecture facts

- Phone, tablet, and TV currently ship in one Android APK.
- Tablet and TV both use the Masjid/display renderer, so changes to `MasjidDisplayPage.tsx` can affect both.
- Phone behavior shares the same `mobile/` app and native Android modules, so Android-wide changes can affect phone, tablet, and TV together.
- Wear OS is a separate native Gradle project under `wearos/`.
- iOS configuration is committed in `mobile/app.config.ts` and `mobile/eas.json`; native iOS files are generated by Expo/EAS when required.
- Web/PWA lives under `pwa/` and is built/deployed separately from the APK.

## Release rule for Android

Before releasing the shared Android APK, verify:
1. Regular Android phone mode.
2. Tablet / large-screen mode.
3. TV / Masjid TV / wall-display mode.
4. Shared notifications, prayer audio, exact alarms, settings persistence, and navigation.

Do not treat a change as tablet-only or TV-only just because the UI entry point is different; if it ships in `mobile/`, it may affect the same APK.

## General rule

Do **not** choose a branch, old version-numbered workflow, or old patch by memory. Always:

1. Start on `main`.
2. Open this file.
3. Route to the correct platform README above.
4. Determine whether the work affects the shared Android APK, iOS, Watch, Web, or more than one target.
5. Inspect the relevant source/workflow before making changes.
6. Treat old release/build branches as history or rollback unless explicitly requested.

Safety rollback made before the platform index was introduced: `backup/main-before-platform-index-2026-09-08`.
